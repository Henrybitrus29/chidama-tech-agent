# API

Base URL: your backend, e.g. `https://your-agent.onrender.com`. All responses are JSON and `Cache-Control: no-store`.

## `GET /api/config`
Public settings for the widget: `business_name`, `assistant_name`, `welcome_message`, `suggested_questions`, `booking_enabled`, `privacy_notice`.

## `GET /api/health`
`{"status":"ok","tenant":"...","chunks":35,"llm_configured":true,"orchestrator":"langgraph","store":"memory"}`. Safe to ping from an uptime monitor.

## `POST /api/chat`
```json
{ "message": "How much is an 8 kW system?", "session_id": "9f3c2d7a1b4e4c60a8d2" }
```
`session_id` is generated by the browser: 16-64 characters from `A-Z a-z 0-9 _ -`. Use a random value (the widget uses 36 hex characters). It keys the conversation, so keep it per visitor and never reuse one across people.

Success `200`:
```json
{ "answer": "An 8 kW system typically costs $20,000 to $24,500 [1].",
  "sources": [{"n":1,"title":"Pricing guide","heading":"Typical residential system prices","snippet":"...","doc":"pricing"}],
  "escalated": false, "session_id": "9f3c2d7a1b4e4c60a8d2" }
```

| Status | Meaning |
|---|---|
| 413 | Body larger than 16 KB |
| 422 | Bad session id, empty message, or message over 4,000 characters (the agent also truncates to `MAX_MESSAGE_CHARS`) |
| 429 | Rate limited (per IP per minute, per session per minute, or per IP per day); honor the `Retry-After` header |
| 503 | `GROQ_API_KEY` is not set, or the all-visitors daily cap (`DAILY_TURN_CAP`) was reached; `Retry-After` is set |
| 500 | Unexpected error; the body is always generic |

## Staff endpoints
Disabled (404) unless `ADMIN_TOKEN` is set. Send `X-Admin-Token`. Call them from a server or a tool like curl, never from a public page.

| Endpoint | Purpose |
|---|---|
| `GET /api/admin/handoffs?status=open\|resolved\|all` | Human-handoff queue with summary and transcript |
| `POST /api/admin/handoffs/{id}/resolve` | Close a handoff |
| `GET /api/admin/leads` | Captured leads |
| `GET /api/admin/bookings` | Appointments |
| `GET /api/admin/stats` | Turns, latency, no-answer rate, flagged/blocked counts, tokens |

## Updating an existing React frontend
```jsx
import { useRef, useState } from "react";

const API = import.meta.env.VITE_API_URL;

function newSessionId() {
  const b = crypto.getRandomValues(new Uint8Array(18));
  return Array.from(b, (x) => x.toString(16).padStart(2, "0")).join("");
}

export function useAgent() {
  const sessionId = useRef(newSessionId());           // one per visitor, kept in memory
  const [messages, setMessages] = useState([]);
  const [busy, setBusy] = useState(false);

  async function send(text) {
    setMessages((m) => [...m, { role: "user", text }]);
    setBusy(true);
    try {
      const res = await fetch(`${API}/api/chat`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ message: text, session_id: sessionId.current }),
      });
      const data = await res.json().catch(() => ({}));
      const reply = res.ok ? data.answer : res.status === 429 ? "Please wait a moment and try again." : "Something went wrong. Try again.";
      setMessages((m) => [...m, { role: "bot", text: reply, sources: data.sources || [] }]);
    } finally { setBusy(false); }
  }
  return { messages, send, busy };
}
```
Render `text` as plain text (React escapes it by default). Do not use `dangerouslySetInnerHTML` on model output.
